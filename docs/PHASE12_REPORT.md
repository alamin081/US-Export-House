## 2. খ-১ — ড্যাশবোর্ড ও রিপোর্ট

- **বিক্রির হিসাব:**
  - অনলাইন অর্ডার "বিক্রি" ধরা হয় প্রথম SHIPPED-এ (ইনভয়েস হওয়ার সময়)। দোকানের বিক্রি ধরা হয় বিল করার মুহূর্তে। এই সময়টা `Order.soldAt`-এ থাকে।
  - বিক্রির সময়ের ক্রয়মূল্য রাখা হয় `OrderItem.unitCostPoisha`-এ। পুরনো লাইনগুলোতে লেখা থাকে "cost unknown"; আন্দাজে কোনো মান বসানো হয় না।
- **হিসাবের নিয়ম:**
  - সময় বাংলাদেশের (UTC+6), সপ্তাহ শুরু শনিবার।
  - Gross → ছাড় → পণ্যের মূল্য → refund, exchange credit আর ফেরত আসা ডেলিভারি বাদ → Net।
- **রিপোর্ট:** বিক্রি, প্রোডাক্ট, লাভ, স্টক, ধীরে বিক্রি হওয়া স্টক, COD, কুপন, রিটার্ন, ব্যর্থ ডেলিভারি, দোকানের ক্যাশ আর স্টক অ্যাডজাস্টমেন্ট।
  - প্রতিটার CSV আছে: UTF-8 BOM সহ, স্প্রেডশিটের সূত্র-আক্রমণ (formula injection) থেকে সুরক্ষিত, stream করা।
- **ড্যাশবোর্ড:** আজকের বিক্রি ও লাভ আর কাজের তালিকা।
  - পাঠানো হয়েছে কিন্তু ৫ দিনেও পৌঁছায়নি এমন অর্ডার, আর ৭ দিনেও COD-এর টাকা না পাওয়া অর্ডার।
  - প্রতিটা সংখ্যায় ক্লিক করলে অর্ডারের তালিকা খোলে।
- **ক্রয়মূল্য কে দেখবে:** শুধু `inventory.cost.read` থাকলে। এখন ব্রাউজার bundle-এ cost field-এর নাম থাকলে CI ফেল করে (`check:bundle`)।

## 3. খ-২ — কনটেন্ট ম্যানেজমেন্ট

- **ডেটার গঠন:** `ContentDocument` (draft আর তার লক) আর অপরিবর্তনীয় `ContentVersion` (DB trigger দিয়ে আটকানো)।
- **এডিটর:** block এডিটর, HTML চলে না।
  - placeholder আছে, যেমন `{freeShippingThreshold}`, `{returnWindowDays}`, `{storePhone}`, `{codMaxTotal}`।
  - `[todo]` নোট থাকলে production-এ publish করা যায় না।
- **Preview:** কাজ করে শুধু তখন, যখন draft cookie আছে **এবং** স্টাফের `content.write` আছে।
- **স্টোরফ্রন্ট:** হেডার, মেনু, ফুটার, হোম আর `/pages/<slug>` এখন DB থেকে আসে।
  - হোম publish না হলে কোডের স্থির কাঠামো দেখায়।
  - ফুটার আর Contact-এ শুধু BRANCH ধরনের শাখা দেখায়।
- **চার শর্ত, বাস্তবায়িত ও টেস্ট করা:**
  1. বানানো তথ্য নেই। নমুনা ডকুমেন্ট production-এ publish করা যায় না, আর প্রথম সেভেই নমুনা চিহ্ন উঠে যায়।
  2. `/account` এখন `/track-order`-এ redirect করে। mock অর্ডার, ঠিকানা আর কাস্টমার ডেটা মুছে ফেলা হয়েছে।
  3. Contact ফর্ম আর নিউজলেটার সরানো হয়েছে।
  4. Audit trigger-এর ব্যতিক্রম শুধু `_test` নামের ডাটাবেসে কাজ করে (খ-৩ দেখুন)।
- **আমদানি (dev, `--apply`):** ১২টা ডকুমেন্ট এসেছে।

| অবস্থা                  | ডকুমেন্ট                                                                      |
| ----------------------- | ----------------------------------------------------------------------------- |
| publish হয়েছে (নমুনা)  | home, announcements, menu.header, footer, about, contact, faq, privacy-policy |
| draft (নমুনা)           | shipping-returns — publish করতে `return.policy.publish` লাগে                  |
| unpublished (নমুনা নয়) | terms, shipping-info, size-guide                                              |

## 4. খ-৩ — Settings, রোল, Audit log, স্থির লেবেল

- **Settings (`/admin/settings`):** কোডে যত সেটিং পড়া হয়, সবই এক registry-তে, ১৩টা গ্রুপে।
  - কোনো মান ভুল হলে পুরো গ্রুপের কিছুই সেভ হয় না।
  - প্রতিটা সেটিং ডিফল্টে ফেরানো যায়।
  - টাকা লেখা হয় টাকায়, জমা হয় পয়সায়।
  - প্রতিটা পরিবর্তন audit-এ যায়, আর কোনো secret দেখানো হয় না।
  - "দোকানের তথ্য" (VAT ছাড়া) আর "SEO ও সোশ্যাল" `content.write` দিয়েও এডিট করা যায়।
- **রোল (`/admin/roles`):** শুধু Super Admin এডিট করতে পারেন।
  - Super Admin রোল আর নিজের রোল বদলানো যায় না।
  - অচেনা permission key নেওয়া হয় না, আর `role.manage` অন্য কোনো রোলে দেওয়া যায় না।
  - একই রোল দুজন একসাথে এডিট করলে পরের জনের সেভ আটকে যায় (CONFLICT)।
  - কোনো স্টাফ যে রোলে আছে, সেটা মোছা যায় না।
- **Audit log:**
  - DB trigger UPDATE, DELETE আর TRUNCATE সব আটকায়।
  - ব্যতিক্রম শুধু তখন, যখন `current_database()` `_test` দিয়ে শেষ হয় **এবং** `SET LOCAL app.audit_purge='on'` দেওয়া থাকে। টেস্টে প্রমাণ হয়েছে যে `us_export_house`, `neondb` আর `…_test_backup`-এ এটা কাজ করে না।
  - Viewer-এ ফিল্টার, এন্ট্রির আগে-পরের পার্থক্য আর মাস্ক করা ফোন (017•••••678) আছে।
  - CSV ডাউনলোডের জন্য `audit.export` লাগে।
- **স্থির লেবেল (`/admin/content/labels`):**
  - সেভ করার জন্য `content.publish` লাগে, আর সেভ করলেই সাইটে দেখা যায়।
  - `{placeholder}` আর plural-এর গঠন অক্ষত না থাকলে সেভ হয় না।
  - লেবেল খালি করলে কোডের মূল লেখা ফিরে আসে।

### ৪.১ স্থির লেবেল: পরিকল্পনায় ~১২০, এখন ২০টা — কেন

পরিকল্পনা লেখার পর খ-২ হোম, FAQ, Contact আর ফুটারের লেখা কনটেন্ট এডিটরে নিয়ে গেছে। ফলে ওই namespace-গুলোতে স্থির লেবেল খুব কম বাকি আছে, আর সেগুলো **সবই** এডিটযোগ্য।

বাকিগুলো এই প্রথম সংস্করণে সতর্কতা থেকে লক রেখেছি। আপনার কথামতো এখন সংখ্যা বাড়াচ্ছি না।

**এডিটযোগ্য ২০টা:**

| Namespace    | Key                                                                                     |
| ------------ | --------------------------------------------------------------------------------------- |
| Common (৬)   | `brandName`, `brandShort`, `brandTagline`, `searchPlaceholder`, `viewAll`, `backToHome` |
| Nav (২)      | `shop`, `trackOrder`                                                                    |
| Footer (৪)   | `visitHeading`, `socialHeading`, `paymentHeading`, `copyright`                          |
| Home (২)     | `categoriesTitle`, `newArrivalsTitle`                                                   |
| Category (৩) | `productCount`, `notFoundTitle`, `notFoundBody`                                         |
| Contact (৩)  | `whatsapp`, `branchesTitle`, `openMap`                                                  |

**বাদ পড়া (পরিকল্পিত namespace-এ এখন ১৭৪টা key):**

| Namespace  | Key       | কেন বাদ                                                                                                                                                                             |
| ---------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product    | ৫২        | সাইজ, স্টক, কার্টে যোগ, ডেলিভারি আর রিটার্নের লেখা। এগুলো দাম, স্টক আর অধিকারের কথা বলে, তাই ভুল লেখা কাস্টমারকে বিভ্রান্ত করতে পারে। ডেলিভারি আর রিটার্নের নোট এখন সেটিং থেকে আসে। |
| Shop       | ৩৩        | ফিল্টার আর সাজানোর নাম কোডের যুক্তির সাথে মিলতে হবে। একটা plural লেবেলও আছে।                                                                                                        |
| Cart       | ৩০        | পরিমাণ, মূল্য আর স্টকের বার্তা। পরিকল্পনাতেও এগুলো "আংশিক" ছিল।                                                                                                                     |
| TrackOrder | ১৮        | অর্ডারের অবস্থা দেখানোর লেখা।                                                                                                                                                       |
| Metadata   | ৮         | সার্চ ইঞ্জিনে দেখানো শিরোনাম আর বর্ণনা। পরিকল্পনায় এগুলো এডিটযোগ্য ছিল, কিন্তু Google-এর তালিকায় চলে যায় বলে এখনো লক রেখেছি।                                                     |

## 5. খ-৪ — প্রোডাক্ট আমদানি, রপ্তানি, ছবির বাল্ক আপলোড

**ফাইল পড়া:**

- **CSV:** UTF-8, BOM থাক বা না থাক। delimiter `,`, `;` বা tab নিজে থেকে চেনে। বাংলা অঙ্ক আর `"1,250"` চলে।
- **Excel:** `.xlsx`-এর শুধু প্রথম sheet পড়ে। সংখ্যা হুবহু লেখা হিসেবে পড়ে, আর সূত্রের ঘরের হিসাব করা মান নেয়। পুরনো `.xls` চলে না, নির্দেশনাসহ জানায়।
- **সীমা (সবই setting):** ফাইল ২ MB, সর্বোচ্চ ৫,০০০ সারি, সব-অথবা-কিছুই-না মোডে ১,০০০ সারি।

**যাচাই (dry run):**

- এই ধাপে প্রোডাক্টে কিছুই লেখা হয় না। পরিকল্পনাটা `ProductImport`/`ProductImportRow`-এ জমা থাকে, ২৪ ঘণ্টা বৈধ।
- **প্রিভিউ:**
  - সারাংশ কার্ড: নতুন, আপডেট, অপরিবর্তিত, ত্রুটি, সতর্কতা।
  - ট্যাব: নতুন, আপডেট (প্রতিটা ঘরের আগে → পরে), ত্রুটি (সারি নম্বর, কলাম আর বাংলায় কারণ), সতর্কতা।
  - ত্রুটিগুলো CSV-তে নামানো যায়: মূল সারি আর একটা `error` কলাম, যাতে Excel-এ ঠিক করে আবার আপলোড করা যায়।

**নিয়ম:**

- **গ্রুপ:** এক সারি = এক ভ্যারিয়েন্ট। সারিগুলো একই প্রোডাক্টে যায় কোড ধরে। কোড না থাকলে বিদ্যমান SKU ধরে (কোডহীন পুরনো প্রোডাক্টও), নইলে নাম আর ক্যাটাগরি ধরে।
- **প্রোডাক্টের ঘর:** সব সারিতে থাকতে পারে, শুধু প্রথম সারিতে থাকলেও চলে। কিন্তু দুই সারিতে আলাদা মান হলে ত্রুটি।
- **ফাঁকা ঘর মানে "বদলাবে না"।** ঐচ্ছিক লেখা মুছতে ঘরে `[clear]` লিখতে হয়।
- **কখনো হয় না:** কোনো প্রোডাক্ট মোছা হয় না। কোনো ভ্যারিয়েন্ট সরে না বা নিষ্ক্রিয় হয় না।
- **কোড:**
  - অজানা `product_code` হলে ত্রুটি। নতুন প্রোডাক্টে ঘরটা ফাঁকা রাখতে হয়; কোড আসে ক্যাটাগরির ক্রমিক নম্বর থেকে।
  - টেমপ্লেটের `EXAMPLE-` দিয়ে শুরু সারি প্রত্যাখ্যাত হয়।
- **অনুমতি:** প্রতিটা কাজ আলাদাভাবে যাচাই হয়; অনুমতি না থাকলে সেই সারি কারণসহ ত্রুটি হয়।
  - লেখা বদলাতে `catalog.write` বা `catalog.content`
  - দাম বদলাতে `catalog.price.write`
  - নতুন প্রোডাক্ট বা ভ্যারিয়েন্ট তৈরিতে `catalog.write`
  - publish বা draft বদলাতে `catalog.publish`
- **ক্রয়মূল্য (`cost_tk`):**
  - শুধু `inventory.cost.read` থাকলে নেওয়া হয়, নইলে পুরো কলাম উপেক্ষিত আর সতর্কতা দেখায়।
  - প্রিভিউতে আসল অঙ্ক দেখায় না, শুধু "•••"।
  - যে ভ্যারিয়েন্টের স্টক movement আছে, তার ক্রয়মূল্য বদলায় না (গড় হিসাবই ঠিক); সতর্কতা দেখায়।
- **publish চাইলে:** ছবি না থাকলে প্রোডাক্ট draft থাকে, কারণসহ। ছবির বাল্ক আপলোড পেজে পরে সেটা "import asked to publish" হিসেবে দেখায়।
- **প্রয়োগ:**
  - শুধু যিনি যাচাই করেছেন তিনিই প্রয়োগ করতে পারেন।
  - একই ফাইল (sha256) আগে আমদানি হয়ে থাকলে নিশ্চিত না করা পর্যন্ত প্রয়োগ শুরু হয় না।
- **সব-অথবা-কিছুই-না:**
  - এক transaction-এ চলে। এর জন্য পণ্য সেভের (`saveProductGraph`) ভেতরের অংশ আলাদা করা হয়েছে, পুরনো আচরণ অপরিবর্তিত।
  - যাচাইয়ের পর কেউ একটা প্রোডাক্ট এডিট করলে (version বদলালে) পুরো আমদানি বাতিল হয়, কিছুই সেভ হয় না, কারণসহ।
- **শুধু ভালোগুলো:** Settings-এ চালু করলে পাওয়া যায় (ডিফল্ট বন্ধ)।
  - প্রতি অংশে ২৫টা প্রোডাক্ট বা ~৮ সেকেন্ড, অগ্রগতির বার দেখায়।
  - থামানো যায়, পরে আবার চালালে যেখানে থেমেছিল সেখান থেকে চলে।
- **Audit:** `catalog.import.checked`, `catalog.import.apply`, প্রতিটা প্রোডাক্টে `catalog.product.import`, দাম বদলালে `catalog.price.import`।

**রপ্তানি:**

- প্রোডাক্ট তালিকায় "Export CSV" বাটন, তালিকার ফিল্টার মেনে চলে।
- আমদানির কলামই একই ক্রমে আসে, তাই ফাইলটা আবার আমদানি করা যায়। টেস্টে প্রমাণ হয়েছে: রপ্তানির ফাইল আবার আমদানি করলে কিছুই বদলায় না।
- `cost_tk` কলাম শুধু অনুমতি থাকলে আসে।
- stream করা, `catalog.export` লাগে, audit হয়।

**ছবির বাল্ক আপলোড (`/admin/products/images`):**

- **ফাইল বাছাই:** ফোল্ডার বা একাধিক ছবি বাছাই করা যায়।
- **নামের নিয়ম:** `{code}_1.jpg` বা `{code}_{রঙ}_2.jpg`; ছোট-বড় অক্ষর উপেক্ষা করা হয়।
- **প্রিভিউ:** প্রতিটা ফাইলের সাথে থাম্বনেইল আর কোন প্রোডাক্টে যাবে তা দেখায়। না মেলা ফাইল আলাদা তালিকায় কারণসহ, আর একই জায়গায় দুটো ফাইল হলে সংঘাত হিসেবে দেখায়।
- **আপলোড:**
  - একসাথে ৩টা (setting), আগের পথেই: ব্রাউজারে ছোট করা, signed token, সার্ভারে যাচাই।
  - বিদ্যমান ছবির পরে "যোগ" অথবা "বদলান", সবার জন্য একসাথে বা প্রতিটা প্রোডাক্টে আলাদা।
  - "বদলান"-এ পুরনো ফাইল storage থেকে মোছা হয় commit-এর পরে।
  - ব্যর্থ ফাইলগুলো আবার চেষ্টা করলে সফলগুলো দ্বিতীয়বার পাঠানো হয় না।
- **শেষে:** যে draft-গুলো এখন publish-এর শর্ত পূরণ করে, সেগুলো এক ক্লিকে publish করা যায় (`catalog.publish`)।

**আমদানির integration টেস্টে যা প্রমাণিত:**

- যাচাইয়ে কিছুই লেখা হয় না।
- নতুন প্রোডাক্ট তৈরি হয়: কোড, SKU আর বারকোড নিজে তৈরি হয়।
- শুধু SKU দিয়ে আপডেট করা যায়: আগে-পরের পার্থক্য আর দামের audit সহ।
- অনুমতি না থাকলে সেই সারি কারণসহ ত্রুটি হয়।
- ত্রুটির সারি নম্বর আর কলাম ঠিক থাকে, আর ত্রুটির CSV তৈরি হয়।
- টেমপ্লেটের উদাহরণ প্রত্যাখ্যাত হয়।
- যাচাইয়ের পর এডিট হলে পুরো আমদানি বাতিল হয়, কিছুই সেভ হয় না।
- একই ফাইল আবার দিলে নিশ্চিত করতে হয়।
- ক্রয়মূল্যের অনুমতির দুই দিকই কাজ করে।
- `.xlsx` ফাইল পড়া যায়।
- রপ্তানির ফাইল আবার আমদানি করলে কিছুই বদলায় না।
- "শুধু ভালোগুলো" মোড কাজ করে।
- বাল্ক ছবি: যোগ ও বদল কাজ করে; জাল token, ভুল রঙ আর অনুমতি না থাকলে আটকায়।

**CI:** প্রতিটা ধাপের push-এ সবুজ। খ-৩-এ `db:verify` দুবার ফেল করেছিল, দুটোই টেস্টের নিজের ত্রুটি, অ্যাপের নয়।

- প্রথমবার: CI-র ডাটাবেসের নাম `_test` দিয়ে শেষ, তাই ফ্ল্যাগ দিলে মোছা সেখানে ইচ্ছাকৃতভাবেই চলে। অথচ চেকটা ধরে নিচ্ছিল মোছা আটকাবে।
- দ্বিতীয়বার: নতুন ডাটাবেসে কোনো audit row ছিল না, তাই trigger চালুই হয়নি।
- এখন প্রতিটা চেক নিজের একটা row বানিয়ে পরীক্ষা করে, তারপর সব rollback হয়।

## 8. নিরাপত্তা

- **Secret:** কোনো secret কমিট হয়নি।
  - `.env.local` আর `.env` git-ignored, আর `git log --all`-এ খালি।
  - Settings-এ কোনো secret নেই; integration-এর অবস্থা শুধু "যুক্ত/যুক্ত নয়" হিসেবে দেখায়।
- **ক্রয়মূল্য:** শুধু `inventory.cost.read` থাকলে দেখা যায়: রিপোর্ট, CSV, আমদানি আর রপ্তানি সব জায়গায়।
  - প্রিভিউতে অঙ্কটা লুকানো থাকে।
  - ব্রাউজার bundle-এ cost field-এর নাম থাকলে CI ফেল করে।
- **কাস্টমারের ফোন:** audit viewer আর audit CSV-তে মাস্ক করা থাকে।
- **Audit log:** DB নিজেই বদল আর মোছা আটকায়; টেস্টের ব্যতিক্রম শুধু `_test` ডাটাবেসে আর ফ্ল্যাগ দিলে।
- **রোল:** কেউ নিজেকে বেশি ক্ষমতা দিতে পারে না, Super Admin রোল বদলানো যায় না, আর `role.manage` শুধু Super Admin-এর।
- **স্টাফের ইনপুট:**
  - কনটেন্টে HTML চলে না, আর লিংক নিরাপদ কি না যাচাই হয়।
  - আমদানিতে HTML ট্যাগ প্রত্যাখ্যাত।
  - CSV রপ্তানিতে স্প্রেডশিটের সূত্র-আক্রমণ থেকে সুরক্ষা আছে; আমদানির সময় সেই সুরক্ষার চিহ্ন সরানো হয়, তাই round-trip ঠিক থাকে।
- **ছবি:** signed upload token ছাড়া কোনো ছবি প্রোডাক্টে যুক্ত হয় না; জাল URL প্রত্যাখ্যাত।
- **Excel পার্সার:** শুধু সার্ভারে চলে, ফাইলের আকারের সীমা আছে, আর আমদানি শুধু `catalog.import` থাকলে।
- **Preview:** draft cookie **আর** `content.write` দুটোই লাগে।

## 9. Mock-এর অবস্থা ও আপনার করণীয়

**Mock-এর অবস্থা:** স্টোরফ্রন্ট আর অ্যাডমিনে আর কোনো mock ডেটা নেই। পরিকল্পনার ১.৩-এর তালিকার সবকিছু এখন DB, content document বা setting থেকে আসে, অথবা সরানো হয়েছে (account-এর mock, Contact ফর্ম, নিউজলেটার)।

বাকি আছে শুধু ইচ্ছাকৃত mock:

| কী                          | কোথায় ব্যবহার হয়                      |
| --------------------------- | --------------------------------------- |
| mock storage (`local-mock`) | টেস্ট, CI, আর Cloudinary ছাড়া dev      |
| COD                         | Phase 10-এর আগ পর্যন্ত একমাত্র পেমেন্ট  |
| কুরিয়ার                    | হাতে চালানো (Steadfast আসবে Phase 11-এ) |
| SMS                         | এই ফেজে নেই                             |

**আপনার করণীয়:**

1. **কনটেন্ট:** about, contact, faq, privacy-policy আর shipping-returns-এ `[এখানে …]` placeholder আছে। আসল লেখা দিয়ে সেভ করুন (সেভ করলেই নমুনা চিহ্ন উঠে যায়), তারপর publish।
   - shipping-returns publish করতে `return.policy.publish` লাগে।
   - terms, shipping-info আর size-guide এখনো লেখা হয়নি।
2. **ক্যাটাগরির কোড:** dev-এর ৪টা ক্যাটাগরিতে (Formal Shirts, Casual Shirts, Polo T-Shirts, Denim Jeans) কোড নেই। আমদানিতে নতুন প্রোডাক্ট তৈরি আর কোড তৈরির জন্য কোড লাগবে, যেমন `FS`, `CS`, `PL`, `DJ`। ক্যাটাগরি পেজে বসান।
3. **পুরনো নমুনা প্রোডাক্ট:** ২৫টার মধ্যে ২৪টার প্রোডাক্ট কোড নেই (Phase 4-এর নমুনা)।
   - আমদানি এদের SKU ধরে চেনে।
   - কিন্তু ছবির বাল্ক আপলোডের নাম মেলানো কোড ধরে চলে, তাই এদের জন্য কাজ করবে না।
   - আসল ক্যাটালগ আমদানির সময় নমুনাগুলো archive করা ভালো।
4. **Settings:** দোকানের ফোন, WhatsApp, ঠিকানা আর সোশ্যাল লিংক দিন। ভ্যাট দেখাবেন কি না ঠিক করুন।
5. **শাখা:** BR-CTG, BR-DHN আর BR-GUL নমুনা শাখা, আর কোনোটার `mapUrl` নেই। আসল শাখা যোগ করুন বা এগুলো ঠিক করুন; ফুটার আর Contact এখান থেকেই দেখায়।
6. **রোল:** `/admin/roles`-এর matrix একবার দেখে নিন। বিশেষ করে Store Manager-এর `catalog.import` আর `content.publish`।
7. **আমদানি একবার চেষ্টা করুন:** আসল স্প্রেডশিটের ছোট একটা অংশ দিয়ে। প্রিভিউ দেখে প্রয়োগ করুন। টেমপ্লেট আর কলামের ব্যাখ্যা আমদানি পেজেই আছে।

## 10. Phase 9.5-এর আগে প্রশ্ন

Phase 9.5 মানে staging deploy। এগুলোর উত্তর ছাড়া শুরু করব না।

1. **হোস্টিং:** Vercel ঠিক আছে কি? কোন অ্যাকাউন্ট বা টিম? প্রজেক্ট আমি তৈরি করব, নাকি আপনি করে আমাকে access দেবেন?
2. **ডাটাবেস:** Neon (আগের সিদ্ধান্ত)। region কি Singapore (`ap-southeast-1`)? staging আর production আলাদা Neon প্রজেক্টে, নাকি একই প্রজেক্টে আলাদা branch-এ?
3. **ডোমেইন:** staging-এর ঠিকানা কী হবে, যেমন `staging.<আপনার-ডোমেইন>`? নাকি আপাতত `*.vercel.app`?
4. **staging কি লুকানো থাকবে?** Vercel-এর পাসওয়ার্ড বা SSO সুরক্ষা দিয়ে, যাতে Google index না করে? আমার সুপারিশ: হ্যাঁ।
5. **Cloudinary:** staging-এর জন্য আলাদা অ্যাকাউন্ট বা ফোল্ডার, নাকি dev-এর অ্যাকাউন্টই?
6. **staging-এর ডেটা:**
   - নমুনা ক্যাটালগ আর নমুনা কনটেন্টসহ (dev-এর মতো, publish করা), নাকি খালি ক্যাটালগ আর শুধু draft (production-এর মতো)?
   - staging-এ `APP_ENV` কী হবে: `staging`, নাকি production-এর নিয়মে চালাব?
7. **স্টাফ অ্যাকাউন্ট:** staging-এ কে কে লগইন করবেন? Super Admin কে হবেন (ইমেইল)? বাকিদের রোল কী?
8. **লেবেল:** এখনকার ২০টা লেবেলেই staging চলবে, নাকি deploy-এর আগে কিছু namespace খুলব (যেমন Metadata)?
9. **`catalog.import.allowPartial`:** staging-এ চালু করে দেখবেন, নাকি বন্ধই থাকবে?

## 11. চালানো ও টেস্টের ধাপ

**লোকালে চালানো:**

```bash
npm run db:up                          # ডাটাবেস (127.0.0.1:55432)
npm run db:migrate:deploy              # নতুন migration থাকলে
npm run dev                            # http://localhost:3000 (পোর্ট ৩০০০ অন্য প্রজেক্টের সাথে শেয়ার করা)
```

**যাচাই:**

```bash
npm run typecheck && npm run lint && npm run format:check
npm test                               # unit
npm run db:test:reset -- --seed        # টেস্ট DB পরিষ্কার করে নতুন করে (শুধু us_export_house_test)
npm run test:integration               # শুধু _test DB
npm run test:e2e                       # build + Playwright (port 3200, mock storage)
npm run build && npm run check:bundle  # bundle-এ secret, cost বা server-only কোড নেই
npm audit --omit=dev
npm run db:verify && npm run inventory:verify
```

**নতুন ফিচার হাতে পরীক্ষা:**

- **রিপোর্ট:** `/admin/reports` → একটা রিপোর্ট খুলুন → সময়সীমা বদলান → CSV নামান।
- **কনটেন্ট:** `/admin/content` → একটা ডকুমেন্ট এডিট করুন → Preview → Publish → History থেকে পুরনো সংস্করণে ফিরুন।
- **Settings:** `/admin/settings` → একটা গ্রুপ বদলে সেভ করুন → `/admin/audit`-এ এন্ট্রিটা দেখুন।
- **রোল:** `/admin/roles`। শুধু Super Admin খুলতে পারেন।
- **লেবেল:** `/admin/content/labels` → `Nav.trackOrder` বদলান → স্টোরফ্রন্টে দেখুন → ঘর খালি করে ফিরিয়ে দিন।
- **আমদানি:** `/admin/products` → Import → Template নামান → নিজের সারি লিখুন → Check file → প্রিভিউ → Import।
- **রপ্তানি:** `/admin/products` → Export CSV। ফাইলটা আবার আমদানি করলে সব "Unchanged" দেখাবে।
- **ছবি:** `/admin/products/images` → `{code}_1.jpg` নামের ছবি বাছুন → Upload → Publish।
